# NoteMaker

Веб-приложение на Python/Flask для работы со статьями: зарегистрированные пользователи загружают статьи в формате PDF и получают их краткое содержание, составленное языковой моделью, а преподаватели могут создавать по статьям экзамены с автоматически сгенерированными вопросами.

## Возможности

- Регистрация: имя, почта, пароль и подтверждение пароля.
- Вход и выход из системы (пароли хранятся в хэшированном виде).
- Роли пользователей: **администратор**, **гость**, **студент**, **преподаватель**.
- Новый пользователь получает роль **«Гость»**. Администраторы создаются
  только через скрипт `create_user.py`.
- Администратор может просматривать список всех пользователей и изменять их роли.
- Все зарегистрированные пользователи могут загрузить статью в формате **PDF**
  и получить её краткое содержание (до 4000 символов), составленное языковой
  моделью через OpenAI-совместимый API (по умолчанию ProxyAPI) или GigaChat.
- **Автоопределение типа статьи**: при загрузке статьи (для краткого
  содержания или экзамена) можно отметить параметр «Определить тип статьи
  автоматически» — модель сравнит статью со списком предусмотренных типов
  (названия и описания задаются администратором) и выберет наиболее
  подходящий. Если статья не относится ни к одному из типов, тип не
  присваивается. После автоопределения предложенный тип можно
  скорректировать вручную, не загружая файл повторно.
- **Экзамены по статьям**: преподаватель загружает статью, и языковая модель
  генерирует 5 вопросов на усвоение материала с правильными ответами.
  Преподаватель может исправлять вопросы и ответы вручную, а также удалять
  вопрос — вместо него модель сгенерирует новый. До завершения работы экзамен
  считается **черновиком** (виден только автору и редактируется), после
  нажатия кнопки «Завершить работу над экзаменом» он становится
  **сформированным** (виден всем преподавателям и студентам, не редактируется).
- Данные хранятся в базе данных **SQLite** (`users.db`).

## Первый запуск

```bash
# 1. Создать виртуальное окружение
python3 -m venv venv

# 2. Перейти в виртуальное окружение
source venv/bin/activate

# 3. Установить нужные пакеты
pip install -r requirements.txt

# 4. Создать учетную запись администратора
python create_user.py --role administrator

# 5. Запустить приложение
python app.py
```

## Последующие запуски

```bash
# 1. Перейти в виртуальное окружение
source venv/bin/activate

# 2. Запустить приложение
```

Откройте в браузере: http://127.0.0.1:5000

## Смена пароля из командной строки

Пароль пользователя можно изменить без запуска приложения с помощью утилиты
`change_password.py`. Она работает напрямую с базой данных `users.db` и не
требует настроенного окружения языковой модели (переменных `.env`):

```bash
# 1. Активировать виртуальное окружение
source venv/bin/activate

# 2. Интерактивный ввод нового пароля (скрытый, с подтверждением)
python change_password.py user@example.com

# Либо передать пароль в командной строке
python change_password.py user@example.com --password "new-secret"

# Либо указать другой файл базы данных
python change_password.py user@example.com --db /path/to/users.db
```

Требования к паролю те же, что и при регистрации: не менее 6 символов.
Пароль сохраняется в хэшированном виде (Werkzeug), так же как при регистрации
через веб-интерфейс.

## Создание пользователя из командной строки

Нового пользователя можно создать без запуска приложения с помощью утилиты
`create_user.py`. Она работает напрямую с базой данных `users.db` и не
требует настроенного окружения языковой модели (переменных `.env`):

```bash
# 1. Активировать виртуальное окружение
source venv/bin/activate

# 2. Имя, почта и роль заданы в командной строке
python create_user.py --name "Иван" --email ivan@example.com --role student

# Либо недостающие данные (имя, почта, роль) будут запрошены с клавиатуры
python create_user.py

# Либо указать другой файл базы данных
python create_user.py --name "Иван" --email ivan@example.com --db /path/to/users.db
```

Роль — одна из: `administrator`, `guest`, `student`, `teacher` (по умолчанию
`guest`). Пароль ВСЕГДА запрашивается только с клавиатуры: ввод скрыт и
требует подтверждения. Требования к паролю те же, что и при регистрации:
не менее 6 символов. Пароль сохраняется в хэшированном виде (Werkzeug).

## Настройка языковой модели (.env)

Параметры обращения к языковой модели задаются в файле `.env`
(создайте его по образцу `.env.example`). Каждый тип LLM использует
свой набор переменных, поэтому для переключения между сервисами
достаточно изменить `LLM_API_TYPE` — ключи доступа хранятся независимо:

| Переменная        | Описание                                                                                               |
|-------------------|--------------------------------------------------------------------------------------------------------|
| `LLM_API_TYPE`    | Тип API: `openai` (OpenAI-совместимый) или `gigachat`                                                  |
| `OPENAI_API_KEY`  | API-ключ для OpenAI-совместимых сервисов                                                               |
| `OPENAI_API_URL`  | URL OpenAI-совместимого API (по умолчанию `https://api.proxyapi.ru/openai/v1` — ProxyAPI)              |
| `OPENAI_MODEL`    | Название модели (по умолчанию `gpt-4o-mini`)                                                           |
| `GIGACHAT_API_KEY`| Ключ разработчика GigaChat (строка в формате base64)                                                   |
| `GIGACHAT_API_URL`| URL GigaChat (по умолчанию `https://gigachat.devices.sberbank.ru/api/v1`)                              |
| `GIGACHAT_MODEL`  | Название модели GigaChat (по умолчанию `GigaChat-2`)                                                   |

> **Важно при использовании GigaChat:** необходимо установить
> [сертификаты Минцифры России](https://www.gosuslugi.ru/crt) (Russian Trusted
> Root CA и Russian Trusted Sub CA). Без них запросы к API GigaChat будут
> завершаться ошибкой SSL-проверки сертификата сервера.

Валидация окружения выполняется в модуле `config.py`: если `LLM_API_TYPE`
имеет недопустимое значение или не задан ключ доступа для выбранного типа
LLM, приложение завершится с понятным сообщением об ошибке.

Обращение к OpenAI-совместимому API выполняется через
`POST {LLM_API_URL}/chat/completions`, для GigaChat access_token получается
автоматически через OAuth 2.0 (`https://ngw.devices.sberbank.ru:9443/api/v2/oauth`).

    style.css             # стили
users.db                  # база данных SQLite (создаётся автоматически)
requirements.txt          # зависимости
